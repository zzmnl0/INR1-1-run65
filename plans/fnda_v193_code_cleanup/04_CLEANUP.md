# S4：分批清理当前执行项目

[返回总体计划](MASTER_PLAN.md#阶段与关系) · 前置：[S3 备份与基线](03_BACKUP_BASELINE.md) · 验收：[S5](05_VALIDATION_HANDOVER.md)

身份：执行经确认的清理清单。状态：未执行；本路线不是现在执行修改的指令。

## 执行顺序

1. 将已备份且判定弃用的独立入口、历史实验脚本和旧模块移出活动项目；保持归档路径映射，不删除历史失败记录。
2. 清理保留模块中的无效分支、未使用导入、重复实现和失效注释。每次修改前搜索全部调用方；重复逻辑优先复用现有共同实现。
3. 更新受影响的入口、配置、导出、测试、示例及操作文档。保留用户实际使用的命令和必要兼容行为，不无故重命名模型类、状态键或公共入口。
4. 保持 `inr_modules/config_mdia.py` 在项目既有配置体系中的角色；先识别有效配置的覆盖来源，再清理确认无用的配置项。动态访问和检查点恢复所需字段保留。
5. 模型、训练、数据、IRI、评估和绘图分别形成小批次；每批运行相关 S5 检查，通过后再推进依赖它的下一批。
6. 仅在现有入口不能明确表达当前工作流时增加最少量组织代码，不引入通用框架或无需求的新依赖。
7. 执行S2的 [C11–C14零权重/禁用分支处置](records/zero_config_review.md)：依据有效配置移除专用调用链，保留校准后非零功能与共享消费者；跳过乘0计算前检查数值、状态与随机性影响，同步配置、恢复读取、记录及测试。

## 每批记录

`records/change_log.md` 记录：清单编号、文件/符号、变更原因、调用方同步项、验证命令及结果、备份对应位置、未决项。修改前核查并发变化，不覆盖其他工作产生的改动。

## 停止与恢复

原检查点无法严格加载、固定输入输出改变、无观测回退改变、数据匹配或评估口径改变时，暂停该批次，保留失败日志并定位。仅恢复该批次相关文件，不整目录覆盖新产生的无关改动。不通过非严格加载、放宽阈值或删除测试掩盖差异。

## 完成条件

每项处置均有实际文件映射和验证证据；活动目录与执行说明一致，保留链路不依赖归档目录，随后交 S5 做整体核对。
