## 输入与路线

1. 从 V19.3 正文、图表来源、投稿构建记录及结果清单提取论文实际报告的实验与比较对象，不以文件名推定模型。
2. 反查结果报告、缓存、运行目录和日志，建立“论文结果 → 评估命令/配置 → 模型检查点 → 模型代码及训练记录”的链路。
3. 记录检查点绝对路径、SHA-256、配置、训练步数/轮次、模型结构标识、预处理版本、IRI 依赖及可获得的 Git 状态。区分训练时配置、评估时配置和当前默认配置。
4. 检查当前工作区相对该模型来源的后续修改和未提交改动。Git 提交、目录时间和权重名称分别记录，不能单独作为身份结论。
5. 覆盖论文实际使用的主模型、消融和比较模型；不能把名称相似的 ETKF 缓存或诊断运行自动当作正式比较结果。
6. 权重来源先确认可信，优先读取已有元数据；需要加载时沿用安全且适配现有格式的项目机制，不执行未知来源对象。

## 输出

实施时生成 `records/model_identity.md` 与机器可读清单，逐条包含结果标识、输入证据、检查点及哈希、入口、配置、代码来源、当前差异、可信程度和未决项。找不到的代码来源明确记为未知，不补写推测的提交号。

## 放行与关系

结果与模型关系可解释且关键歧义经用户决定后，S1 放行。身份清单交给 S2 定义保留链路，交给 S3 确定备份和基线对象，交给 S5 选择原权重与评估样例。若存在多个候选，提交证据比较及推荐，未解决前不据此删除代码。
