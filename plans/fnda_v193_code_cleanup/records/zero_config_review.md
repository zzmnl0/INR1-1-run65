## 范围与判断方法

此前S2已包含部分关闭分支，尚未逐项覆盖零值参数。本次新增29个参数的核查矩阵，覆盖当前 `CONFIG_MDIA` 字面默认值、主模型及三个敏感性run的初始配置、resolved_training和summary；每项记录源码引用位置。包括相关False开关和必要的非零对照，不将所有0统称为无用模块。

处置顺序为：默认值 → 命令行/入口覆盖 → 阶段条件 → 校准所得权重 → checkpoint恢复值 → 实际消费者。只有保留工作流中始终不生效、且无共享或状态依赖的专用实现，才列为迁出或删除候选。某文件标为KEEP，不代表其内部零权重分支必须全部保留。

新shape/adapter/anchor/gate-balance/M00键在历史manifest多为NOT_RECORDED，并不等于显式False；当前fallback与后续研究分支的解析仍随C01–C07核实。背景bias校准权重在N4D64为0.015236347148194305、N8D32为0.01464220248565664、N8D64-reproduction为0.015319562115810564，三个敏感性运行均实际启用。

## 两类实现处理规则

**完全不执行的分支**：先确认所有保留run与恢复路径均关闭，再将专用定义、调用点、配置说明、日志及专用测试成组迁出；模块中共用部分保留。兼容字段可以保留读取而不保留完整训练实现。

**计算后乘0的分支**：在S3固定清理前损失、输出及状态；S4如跳过计算，验证数值、梯度、随机状态和日志语义。不能仅凭数学上的0认定程序行为完全等价。本轮只登记审查位置，没有认定新的运行时性能问题。

## 与后续阶段连接

- S3：保存入口覆盖/校准/恢复前后的有效配置；记录低高度及背景bias非零事实；为拟跳过分支固定必要状态和输出。
- S4：按C11–C14落实专用计算链精简，搜索全部调用者，同步配置、恢复读取、报告及测试；保留主/S6启用的低高度、Gram、频谱与bias路径。
- S5：比较主模型与S6相关路径的输出、损失、梯度、冻结参数、checkpoint加载与恢复；不能只验证脚本能启动。
